## 1. 研究目标与版本边界

研究问题是：学生能否完成查找赛事、核对规则、理解推荐、选择组合和推进项目；哪些流程有耗时收益，哪些位置仍然造成障碍。

本轮材料补充基于仓库提交 `e2fb1b30fa2e0f22872f41f51a6c9ba19db7ac21`。这是整理材料时审查的源码版本，不是已证明的试用版本。工作簿未提供可独立核验的试用应用提交、赛事数据快照和原始执行日志之间的对应关系，不能将这些结果归因于某次 GitHub 更新。

统计限定为工作簿标注的离线运行记录，不用于证明在线模型规划、真实通知自动同步、真实队友招募、获奖率或生产部署效果。

## 3. 任务定义与统计方法

团队称成功判据取自工作簿 `01任务卡`。以下为仓库已提供的摘要，机器可读结果保存相同摘要；当前没有源工作簿，无法复核更完整的判据或执行是否符合判据。

| ID | 模块 | 成功判据摘要 | 时间上限 |
| --- | --- | --- | ---: |
| T01 | 能力画像 | 保存、重开后关键字段一致，未丢失或串号 | 90秒 |
| T02 | 赛事大厅检索 | 找到指定赛事、年份和赛道，清空后恢复列表 | 90秒 |
| T03 | 赛事规则与来源 | 截止、人数和材料与答案卡一致，并找到依据；未知保持未知 | 180秒 |
| T04 | 我的推荐 | 至少一条相关推荐通过资格、截止及引用版本核验，学生能说明原因 | 180秒 |
| T05 | 科创机会组合 | 至少一套方案满足真实工时与截止约束，理解下一步，未擅自写入 | 240秒 |
| T06 | 项目执行 | 明确采用后才写入，能推进任务、有效导出并保持重开状态 | 240秒 |
| T07 | 智能顾问 | 规则与追问符合答案卡，赛事、年份、版本及引用可核对 | 180秒 |
| T08 | 边界与安全兜底 | 对指定异常输入正确拒绝或要求确认，不编造或越权写入 | 120秒 |
| T09 | 赛事雷达 | 在受控变化中找到影响、区分审核状态并理解应处理事项 | 120秒 |
| T10 | 组队与互补建议 | 理解建议及角色缺口，无虚构真实匹配或信息泄漏 | 120秒 |

已开始分母包含独立成功、协助成功、失败、超时和中途退出。未开始、不适用单列，不自动算成功。

`总成功率 = (独立成功 + 协助成功) / 已开始的纳入尝试`。

`独立成功率 = 独立成功 / 已开始的纳入尝试`。

当前复算脚本以公开聚合计数为输入，验证总数与分母并重算百分比；均分、计时均值、逐对节省比例等只能保存团队报告值，缺少个人行和计时行时不能重新算出这些指标。不同任务采用各自分母。安全兜底成功不混入找到合适赛事的成功率。

## 5. 推荐评价

329条有效评价的用户相关性均分3.26/5。评分至少4分的148条，占45.0%。相关门槛、资格符合、未截止、来源版本一致及核验字段完整同时满足的111条，占33.7%。

这是推荐条目的评价比例，不是学生人数比例或模型准确率。团队报告329条来自148人，同一学生可评价多个条目，不能当作329个独立参与者。官方核验状态沿用团队报告，本次未读取表内原始行或逐一重访官网。其余42名纳入参与者没有评价行，需要区分无候选、未评价和采集遗漏。

分析结论：推荐解释和有效候选覆盖仍有改进空间；不能仅凭T04的保留子集完成率断言整体推荐质量已经充分解决。

## 7. 效率对照

120组中76组满足纳入条件、可比性通过、双方独立成功、正确性通过、正数计时、系统无提示及证据索引非空。

| 指标 | 结果 |
| --- | ---: |
| 人工方法平均耗时 | 323.1秒 |
| 系统方法平均耗时 | 277.2秒 |
| 配对平均少耗时 | 45.8秒 |
| 逐对节省比例的均值 | 14.3% |
| 系统比人工更慢 | 16/76组 |

逐对比例均值与“均值差除以人工均值”不是同一统计量，本节使用前者。证据索引非空不代表原始计时凭证已核验，120到76组的纳入规则应与原始记录共同保存。

分析结论：这76组双方独立成功的可比任务中存在记录上的耗时收益，不外推为所有用户、全部任务或失败尝试均提速14.3%，不构成随机对照研究或因果结论。
